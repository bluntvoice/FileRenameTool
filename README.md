# FileRenameTool

FileRenameTool 是一款面向多轮修订文件的轻量命名工具，适用于合同、制度、方案、报告等需要反复修改并保留多个版本的文件。软件针对日期、版本号、版本类型和公司简称等常见命名要素进行了适配，可自动识别已有版本、递增版本号、清理旧命名并保留原文件扩展名，帮助个人和团队保持文件名称清晰一致。

如果需要正则匹配、批量替换、文件整理等更通用的重命名功能，推荐使用 [OncePower](https://github.com/ilgnefz/once_power)。

双击最新版 [FileRenameTool-v2.6.exe](./FileRenameTool-v2.6.exe) 即可使用，无需安装其他插件。复制给其他人时，只需复制这个 EXE 文件。

完整的结构化更新记录见 [CHANGELOG.md](./CHANGELOG.md)。

## 命名规则

默认格式：`文件名-YYYYMMDD-v版本号-版本类型.扩展名`

“包含日期”“包含版本号”和“包含版本类型”可以分别勾选，用于决定常规命名中是否加入对应要素。勾选“仅保留文件名”后，该模式优先级最高，会忽略日期、版本号、公司简称和版本类型，只输出 `文件名.扩展名`。

示例：

- 初次处理：`合同.docx` → `合同-20260716-v1.0-修订版.docx`
- 公司简称：`合同.docx` → `合同-20260716-v1.0-XX修订版.docx`
- 再次处理：`合同-20260716-v1.0-XX修订版.docx` → `合同-20260716-v1.1-XX修订版.docx`
- 版本进位：`v1.9` → `v2.0`
- 自动去除复制尾缀：`合同（1）.docx` → `合同-20260716-v1.0-修订版.docx`
- 仅保留文件名：`合同-20260716-v1.2-XX修订版（1）.docx` → `合同.docx`
- 仅保留文件名：`合同-20260716-v1.2-XX修订版（1）.docx` → `合同.docx`；即使日期或版本号此前处于勾选状态也不会加入名称
- 日期紧贴类型：`合同-20260716修订.docx`、`合同（20260716）修订版.docx` → 自动识别旧日期并更新为当日日期
- 清理独立版本号：`合同-v1.2.docx`、`合同-v1.X.docx` → `合同.docx`
- 手动文件名部分：选中 `合同.docx`，将“文件名部分”改为 `采购合同` → `采购合同-20260718-v1.0-修订版.docx`
- 类型自动替换：`合同-20260718-v1.2-清洁版.docx` → `合同-20260718-v1.3-Reviewed Version.docx`
- 可选版本类型：取消“包含版本类型”后，`合同-20260718-v1.2-清洁版.pdf` → `合同-20260805-v1.3.pdf`
- 英文类型：内置 `Reviewed Version`、`Revised Version` 和 `Clean Version`，其中 `Revised Version` 位于 `Reviewed Version` 下方
- 英文类型自动分隔：公司简称为 `XX`、类型为 `Reviewed Version` → `合同-20260718-v1.0-XX Reviewed Version.docx`
- 自定义类型：输入并记住 `客户定稿版` → `合同-20260718-v1.0-客户定稿版.docx`
- 新建空白文件：输入 `采购合同` → 创建 `采购合同-20260718-v1.0-修订版.docx`
- 不含版本号：`会议纪要.docx` → `会议纪要-20260716-XX审核版.docx`
- 更新无版本文件：`会议纪要-20260601-清洁版.docx` → `会议纪要-20260716-XX审核版.docx`

## 使用方法

1. 在“公司简称”中输入文字；允许留空，程序会自动保存最后一次输入的内容。
2. 如需长期保存某个简称，点击“记住简称”，以后可直接从下拉列表选择；点击下拉项右侧的 `×` 即可删除该项记忆。
3. 在“版本类型”中选择内置类型，或直接输入自定义类型；内置英文类型依次包括 `Reviewed Version`、`Revised Version` 和 `Clean Version`。点击“记住类型”后会加入下拉列表，自定义项可通过右侧 `×` 删除。程序也会记住最后使用的类型；公司简称与英文版本类型组合时会自动加入空格。
4. 工具会自动识别规范文件名中已有的清洁版、修订版、英文类型或自定义类型，并替换为当前选择的类型，不会重复追加。
5. “包含日期”“包含版本号”和“包含版本类型”默认勾选，三者可以独立开关；取消“包含版本类型”后，公司简称和修订版、清洁版等版本类型都不会写入新文件名。
6. 将一个或多个文件拖入窗口，或者点击“添加文件”。
   - 一次加入一个文件时，程序会自动选中该文件，便于立即调整“文件名部分”。
   - 一次加入多个文件时不会自动选择，由你手动确认需要操作的文件。
7. 单选列表中的文件后，可在“文件名部分”中手动调整名称，点击“应用到选中”或按 Enter；点击“恢复自动”可撤销本次手动调整。
8. 点击“另存为新文件”会按预览名称复制当前选中的一个或多个文件，原文件保持不变；原文件和新文件都会自动解除只读属性。
9. “执行重命名”默认会先解除源文件的只读属性；如不需要重命名，可选中文件后点击底部的“仅解除只读”。
10. 如需清除日期、版本号、公司简称和版本类型，勾选“仅保留文件名”；该选项会暂时禁用其他命名选项，并清除末尾的 `(1)`、`（2）` 等复制标记。
11. 文件名中的日期即使与“修订”“清洁”等文字紧贴，或使用下划线、括号、`YYYY-MM-DD` 等常见形式，程序也会识别并在需要日期时替换为当天日期。
12. 已符合“文件名-日期-v版本号”或“文件名-v版本号”格式的文件再次处理时，会自动递增版本号；目标名称已存在时会继续递增到可用版本。
13. 点击“新建空白 DOCX”，输入文件名部分并选择保存位置，即可按当前命名选项创建可直接编辑的空白 Word 文件。
14. 点击右上角图钉按钮可保持窗口置顶；再次点击即可取消置顶。
15. 在列表中确认新文件名预览，然后点击“执行重命名”。
16. 关闭主窗口后程序会继续在系统托盘运行；双击托盘图标或选择“打开主界面”可恢复窗口，选择“退出”才会结束程序。
17. 点击底部“关于”，可查看当前 EXE 的真实版本号、作者和 GitHub 仓库地址。

工具始终保留原文件扩展名；`.docx`、`.pdf`、`.xlsx`、`.pptx` 等不同后缀不会影响日期、版本号和版本类型的识别与更新。如果目标文件名已经存在，会继续递增版本号，避免覆盖。

简称和自定义类型设置保存在每位用户自己的 Windows 应用数据目录中，不需要与 EXE 一起复制；其他使用者会拥有各自独立的记忆。
